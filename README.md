# forgeloop

**Beyond Prompt-Ship-Chunk and Pray** — open-source companion code and runnable
notebooks for building, testing, and grounding trustworthy agentic AI systems on
a geometric memory substrate.

| Directory | Package | Focus |
|---|---|---|
| [`beyond-prompt-and-pray/`](beyond-prompt-and-pray/) | `agentlab` | Building agentic AI systems: the agent loop, typed tools, governance, memory, evaluation, and a capstone banking agent. |
| [`beyond-ship-and-pray/`](beyond-ship-and-pray/) | `gmstest` | Testing agentic systems: DoE-driven test design, component and system attribution, resilience. |
| [`beyond-chunk-and-pray/`](beyond-chunk-and-pray/) | `book_kit` | Trustworthy RAG with geometric memory: triple-mediated retrieval, grounded synthesis, self-verification, calibrated abstention. |
| [`beyond-vibe-and-pray/`](beyond-vibe-and-pray/) | `reasonloop` | A semantic execution substrate: the LLM as compiler and grounded synthesizer over a deterministic reasoning engine. *(Work in progress.)* |

## Setup — once, for everything

```bash
git clone https://github.com/knowlytix/forgeloop.git && cd forgeloop
make install
```

One command, all four books. Nothing to add to `PYTHONPATH`, no per-book install,
no ordering to get right. It pulls a few GB — mostly `torch` and `transformers`.

Then pick what you came for.

## 1. Learn with the notebooks

```bash
jupyter lab
```

Open any notebook under `beyond-*/notebooks/` and run it top to bottom. Chapters
are numbered in reading order; each pairs a concept notebook with an
`NN_capstone` that adds that chapter's layer to a running banking complaint agent.

Notebooks that use plain Python run immediately. The rest need the **GMS
substrate** — two one-time steps:

**Step 1 — licence key.** `knowlytix` is already installed, but running it needs a
key. Sign up at <https://knowlytix.ai/signup/>; the flow writes
`~/.knowlytix/license.key` and records acceptance in `~/.knowlytix/eula-accepted`.
Keep the key private — never commit it. Verify:

```bash
python -c "import knowlytix"    # prints a banner naming the licensed customer
```

**Step 2 — build the stores.** Run the setup notebook for the book you are
reading:

```
beyond-prompt-and-pray/notebooks/00_setup.ipynb    building governed agents
beyond-ship-and-pray/notebooks/00_setup.ipynb      testing them
beyond-chunk-and-pray/notebooks/00_setup.ipynb     grounded RAG
```

It checks its inputs first, prints what it will build, and is idempotent — re-run
it freely. Tier 1 is CPU-only and covers most chapters; Tier 2 downloads
`Qwen3-4B-Instruct` (~8 GB) and wants a CUDA GPU.

Trained weights and stores are never committed; `00_setup` rebuilds them from the
corpora in the repo. The pinned campaign results those chapters evaluate against
*are* committed, so the analysis notebooks work without re-running a campaign.

> *`litellm` wheel fails to build?* Recent versions need a Rust toolchain and have
> no prebuilt wheel on some platforms. `knowlytix` only requires `litellm>=1.40`,
> so run `pip install "litellm==1.74.9"` first.

## 2. Read the User Guide

The User Guide, API Reference and a rendered gallery of all 114 chapter notebooks
build into one offline site:

```bash
pip install -r docs/docs/requirements.txt
make docs
open docs/docs/_build/html/index.html      # xdg-open on Linux, start on Windows
```

Takes a few minutes. The site is not hosted or committed — at ~130 MB against a
5 MB repo, and with HTML diffing badly, every rebuild would bloat git history.

Prefer not to build? GitHub renders the sources directly:

- User Guide — [`docs/2-user-guide/`](docs/2-user-guide/), one file per chapter
- Chapter notebooks — `beyond-*/notebooks/`

The API Reference is generated by autodoc from the docstrings, so it never needs
regenerating by hand. It documents the `knowlytix` substrate too — 87 of its ~194
pages — and **no licence key is needed to build those**: the key gates runtime
use, and autodoc only reads signatures.

## Contributing

**The book directories are the source.** `forgeloop/` and the docs gallery are
assembled from them:

```
beyond-*/                    ← edit here
   │  scripts/build_forgeloop.py
   ├─► forgeloop/                   the installable package (committed)
   └─► docs/4-notebook-examples/    the docs gallery (generated, git-ignored)
```

Assembly rewrites imports book-local → package (`agentlab` → `forgeloop.agents`,
`gmstest` → `forgeloop.testing`, `book_kit` → `forgeloop.rag`), so the books stay
runnable from a checkout while the package ships one `forgeloop.*` namespace.
`forgeloop/` is committed so `pip install` and autodoc work with no build step —
**do not edit it by hand**, CI checks it against the books. Package-level files
with no book source live in [`packaging/`](packaging/).

```bash
make install-dev    # everything, plus pytest and ruff
make check          # exactly what CI runs
make assemble       # rebuild forgeloop/ and the docs gallery
```

`make check` runs the four CI gates: `ruff`, no committed notebook output,
`forgeloop/` matching the books, and the test suites. Green locally means green in
CI. Tests needing `knowlytix` skip automatically when it is absent.
